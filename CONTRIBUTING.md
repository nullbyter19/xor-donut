# Contributing

Thanks for taking the time to contribute.

## Workflow

1. Fork the repository and create a topic branch: `git checkout -b feat/short-name`.
2. Keep changes focused and small; one logical change per pull request.
3. Match the existing style and keep comments in English.
4. Build and test locally before opening the pull request.
5. Open the pull request using the template and describe the motivation and the
   verification you performed.

## Commit messages

Use the conventional prefixes `feat:`, `fix:`, `docs:`, `refactor:`, `test:`,
`chore:`. Write the subject in the imperative mood, at most 72 characters.

## Security

Never commit credentials, tokens, private keys, customer data or real
infrastructure hostnames. Use `example.com` and the reserved documentation
ranges (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) in examples.

Report vulnerabilities through the process in [SECURITY.md](SECURITY.md), not
through a pull request.
